## 0. 一枚要約（最重要の10件）

1. **自動配線は「完成したか」でしか評価しない。** 9系統のツールを同一基板・同一条件で反証テストし、固定条件で完成したのは KiCad Routing Tools（KRT）だけだった。自己申告が正直なツールと嘘をつくツールが混在するので、独立検査なしの「成功」は信用しない（§1.2、§2）。
2. **合格条件は4指標で定義する**（未接続・異ネット接触・物理違反・説明不能な変換差分、すべて0、かつ検査が実際に実行された場合のみ）。未配線が残る盤面では指標は null（未測定）として扱い、「ほぼ合格」を作らない。
3. **ボトルネックは層数や面積ではなく、MCU 等の混雑部品からの引き出し（escape）。** 残接続は幾何的に1部品のパッドに集中していた。4層化より先に混雑部の構造を見る。
4. **機構（取付穴・コネクタ操作空間）は配線の前に決める。** 後付けは全体再配線になる。コネクタのサービス領域は実ハウジング寸法＋工具＋手指で検証する（公差で消える 0.025mm の余裕は余裕ではない）。
5. **電源は「最悪感度包絡」で予算化し、設計負荷とストレス条件を分ける。** 供給元が「5V」と名乗っても安定化されていないことがある（HALL_5V はロードスイッチ経由の生 VBUS）。要件は「どこで測る値か」まで書く — 境界条件の転記ミスが実際に開発を止めた。
6. **条件は製品要求から固定し、緩和は「測ってから」判断する。** 価格で条件を守る利益は小ロットでは小さい（2層→4層の差は5枚で +$4）。実現可能性を先に特定し、費用はその後。
7. **スイッチ等の主要部品は、メーカー推奨の基板パターンを基板設計の前に確認する。** 推奨着座条件（位置決め穴・センサ実装面）が後から判明すると Wing 全体の改版になる。
8. **評価基板で物理量を測ってから量産設計を凍結する。** ピッチのような感覚＋物理の混ざる量は、候補を全部作って実物で決める（両ピッチ発注しても $19.20）。
9. **決定は決定記録（D-xxx）に残し、履歴は書き換えない。** 改定は新番号か Amendment で追記する。3週間後に「なぜこの条件か」を証跡つきで再構成できるのが効く。
10. **ワーカー（AI）には停止条件を先に渡す。** タイムボックス、試行回数の上限、「条件を緩めて合格にしない／成立しなければ報告して止まる」を Issue に明記すると、不合格の報告が資産になる。

## 1. ツール評価

### 1.1 EDA オーサリング経路（tscircuit / JITX / KiCad）

| 経路 | 実績 | 判定 |
| --- | --- | --- |
| tscircuit（KiCad からの自動 import） | フットプリント変換で銅箔 keepout 2件が**警告なく消失**、角丸パッド形状も不一致（#13、EDA-003A） | import 経路は不採用。変換ロスは無言で起きる前提で、使うなら等価性ゲート必須 |
| tscircuit（native TSX で新規設計） | 電気的な設計源としては成立し、評価フィクスチャの権威になった（D-014）。ただし内蔵ルーターは異ネット銅箔を生む回帰があり（D-018）、物理配線は任せられない | 電気設計源としては可。物理バックエンドとしては不可 |
| JITX | ソースレベルの配線・部品モデリング・電気的等価は良好。しかし固定環境で headless の多層グローバル配線ワークフローが実証できず（未接続39件残存、D-016） | 物理バックエンド NO-GO（プロジェクト適合性の判断。一般的な能力の否定ではない） |
| KiCad（物理バックエンド＋検査） | DSN/SES 往復と KiCad 自身の読戻し検査が、最終的な製造データと独立検証の基盤になった | 物理設計・検証の本命。バージョンは 9.0.9 で固定して運用 |

教訓：
- **コード駆動 EDA の価値は「設計源の再現性」であって「配線の自動化」ではない。** 配線は別ツール＋独立検証で担保する。
- 変換ツール（importer / converter）は必ず等価性ゲート（ハッシュ固定した入力との全項目照合）を前段に置く。ロスは警告なしに起きる。

### 1.3 検証・検査の道具立て

- **独立読戻し**：配線したツールとは別の経路（KiCad 本体での再充填＋DRC、静的な幅実測、CAM 照合）で測る。ツールの自己申告は証拠にしない。
- **等価性ゲート**：入力基板はハッシュ固定し、変換・往復の前後で「配線追加以外の変更ゼロ」を差分検査する。ゲート項目の一部を事後確認に回した #113 の手順不足は、#115 で実行前完遂に改めた。
- **スモークゲート（Stage 0）**：本基板の前に小基板で「往復できるか・検査が機能するか」を潰す。Stage 0 で落ちた候補に本基板を回す時間を使わない。
- 製造データは Gerber ビューア確認＋ドリル分類・外形・NPTH・銅箔の解析照合までやって初めて「発注可能」と言う（#147）。

### 1.4 AI ワーカー（Codex / Copilot CLI）

デバイス開発の実装ワーカーとしての実績（PMO 運用の知見）：

- **Codex**：長時間の自律実行（2〜4時間枠）に耐え、指示書の停止条件を守る（条件矛盾を指摘して正しく止まった実績、#167）。制約：サンドボックスの都合で GitHub へ push できない（コミットは作業ツリー内のコピーに残り、push はホスト側で行う）、作業ディレクトリと信頼設定を誤ると読み取り専用で無言に失敗する。
- **Copilot CLI**：Codex 枯渇時の受け皿として実務に耐えた（#133 の費用確認など）。別モデルでの第二意見（レビュー・設計判断）にも価値がある。月次のプレミアム枠が上限なので、回復待ちで済む作業には使わない。
- 共通：**成果は Draft PR で受け取り、独立レビュー（数値のスポット照合・差分確認）を通してから次に進む。** ワーカーの「完了しました」は §1.3 と同じく自己申告として扱う。
- クォータの形：Codex は 5時間枠と週間枠の**両方**に残量がないと動かない（片方 0% で全停止）。週間枠は重い日が2日続くと枯れる量だった。プロジェクトが複数ある場合は優先順位を先に決め、枯渇したら止まったタスクをキューに登録して回復を待つ運用が回った。

### 1.5 筐体 CAD

- **build123d（Python / OpenCascade 系）が headless 環境で実証済み**：基板寸法のプレート＋穴生成、STEP／STL／DXF 出力を確認。GUI CAD（FreeCAD 等）はこの種の自動化環境には不適。
- 寸法は基板側の座標データ（JSON／CSV）から駆動する。**取付穴の座標表を基板⇔筐体のインタフェース成果物として残す**（#149）と、両側が同じ真実を参照できる。
- 印刷は自宅 Ender-3 Pro 前提（FDM の精度・反りを前提に、ねじ・嵌合の公差は実物合わせが要る）。仕上がりが必要なら JLCPCB の印刷発注が選択肢。

### 1.6 製造（JLCPCB）の実測事実

価格は 2026-11-04〜05 の実見積もり（48×44mm・1.2mm・HASL・素基板5枚、送料・税別）：

- 基板単価：2層×5枚 **$4.00**／4層×5枚 **$8.00**。小ロットでは層数の価格差は誤差級。発注数量は **5,10,15… の刻み**（「6枚」は選べない — 両面リバーシブルで6枚＝3セット、という計画は立てられない）。
- **0.10/0.10mm は追加料金なし**：2層 1oz の標準能力内、多層でも同様（#133）。線幅公差は ±20%（0.10mm 線で 0.08〜0.12mm — 電源計算にはこの最悪値を入れる）。
- Wing 素基板：16mm $9.30／17mm $9.90（各5枚、エンジニアリング費 $4 込み）。両ピッチ合計 $19.20。
- **左右一体パネル化は効く**：左右を1枚にすると 16mm $14.90／17mm $16.10（5ペア分）で、別々より約 $3.7（約19%）安い。主因はエンジニアリング費が1回分になること。ただし「1デザイン扱い」の見積もりであり、メーカーが複数デザイン／面付けと判定すると変わりうる。分離は自宅で行う前提で、配線を傷めない分離接合（マウスバイト等）を設計要件に入れる。
- Main の PCBA 総額（計画確定値）：5枚 **$91.11（1枚 $18.22）** ＝ 基板 $8.00＋部品 $23.95＋実装・検査 $59.16（X線検査の予算、PTH 脚の手はんだ工程費を含む。調達余剰・送料・税は除く）。見積もりの精度はこの水準で十分と判断し、本人アカウントでの精密見積もりは省略した（PO 判断）。
- **Economic PCBA は片面実装のみ。** 両面実装は Standard が必要で、費用前提が一段変わる（ver.A Wing の両面案は別見積が必須、#158）。部品は Basic 優先で設計すると Extended のフィーダー費（種類数課金）を抑えられる。電源コンデンサの誘電体は X7R に固執せず Basic の X5R で足りた（#124、耐圧・容量・サイズの照合つき）。
- **POFV（エポキシ充填＋銅キャップ）**：via-in-pad が25箇所あっても、配線を変えず発注時に POFV を明示指定するのが正解だった（D-022）。増額は発注時に確定。NPTH や J1 の PTH 脚は充填対象外と明示する。
- USB J1 のような PTH 固定脚つき部品も、Economic の同一発注で SMT と一括実装できる（手はんだ工程費 $0.0164/接点＋$3.58/発注、5枚で $3.908、D-022）。
- 「Keyboard Design」加算の該当性は形状実測では非該当と自己判定できたが、確定はメーカー審査 — **発注してみないと分からない費目は残る**前提で予算を見る。

## 2. 進め方の方針

### 2.1 ステージ制とゲート

- 大きい仕事は **Stage 0（スモーク／等価性）→ Stage 1（単一条件の本実行）→ 採用判断** に割る。各 Stage の合格条件と停止条件を着手前に文章で固定する。
- 「有望そう」では次に進まない。ゲートは §0-2 の4指標のような**機械的に判定できる条件**にする（CI の成功はゲートの代わりにならない）。
- 不合格の報告は失敗ではない。反証テストの目的は候補を落とすことにもあり、落ちた理由と証跡が残れば次プロジェクトが同じ穴を踏まない。

### 2.2 条件の固定と緩和

- 固定条件は製品要求から導く（例：板厚1.2mm はスイッチの磁束データの前提＝物理量。0.20mm は製造限界ではなくプロジェクトのクリアランス要求）。
- 条件に行き詰まったら、条件を疑う前に**行き詰まりの構造を測る**（残接続の端点分布、DRC の実績最小値など）。今回は「残りは全部 MCU のパッドに集中」が分かり、緩和の効く場所と効かない場所が切り分けられた。
- 緩和は段階的に測る（0.20 → 0.127 → 0.10）。採用した条件は決定記録にして、旧条件の文書には履歴注記を足す（書き換えて消さない）。
- **価格を理由に条件を守るのは、小ロットでは割に合わない**ことが多い。数量前提（5枚刻み）を先に置いてから価格議論をする。

### 2.3 要件の書き方（#167 の教訓が核）

- 要件には**「どこで・何を・どの負荷で」測る値か**を書く。検討フェーズの比較境界（例：「変換器入力 4.75V を境界として方式比較した」）を、後段の Issue に**保証要件として転記してはいけない** — USB 源の下限自体が 4.75V では、入力 4.75V の保証は原理的に不可能で、ワーカーが正しく停止した（#167、再定義 D-027 で解決）。
- 保証する範囲（設計負荷）と、保証しないが耐性を見る範囲（ストレス条件）を分けて書く。両方を保証にすると設計が成立しなくなる。
- 指示書の不整合（スモーク基板に存在しないネットを前提にした指示、#117）は PMO 側の欠陥として記録し、ワーカーの成果とは分けて扱う。**止まった原因の所在を曖昧にしない**ことが、次回の指示書の質を上げる。

### 2.4 役割とゲート（PO / PMO / ワーカー）

- PO（人間）：要求・優先順位・方式採用・マージ・発注／課金の最終判断。
- PMO（AI）：Issue 分解、指示書、ワーカー振り分け、タイムボックス、成果レビューと差し戻し、停止／継続判断、証跡の記録。
- ワーカー（AI）：Issue の範囲内だけを実装し、Draft PR で納品。範囲外の問題は PR に記録して提案に留める。マージはしない。
- この分業で効いたのは、**「採用」と「実行」の分離**と、PMO が軽作業（文書・小調査・価格確認）を自分で巻き取ってワーカーの枠を重い実装に温存したこと。

### 2.5 記録の作法

- 決定記録は連番（D-xxx）で append-only。覆す場合は新番号で supersede を明記し、旧記録は残す。
- 文書（docs/）を source of truth とし、ダッシュボードやステータス表示は読み取り専用の写しと位置づける（governance.md）。
- PR は squash merge のみ。証跡ファイル（ログ、検査結果、設定の読戻し）は PR に含めて残す。

## 3. 最初に決めるべきゴールと制約（立ち上げチェックリスト）

実プロジェクトで「後から効いた」順に並べた。着手前に最低限これだけは文章で固定する。

### 3.1 製品・物理の前提

- [ ] **主要部品の物理前提**：スイッチ／センサ等のメーカー公表条件（基板厚、推奨パターン、磁束・感度データの測定条件）。板厚 1.2mm はこの前提から来た制約で、変えるなら物理量の再測定が要る
- [ ] **評価で測る項目のリスト**：量産基板を出す前に評価基板で測るもの（本件では travel 曲線と極性、ADC スパンとクリッピング余裕、ノイズと再現性、mux セトリング、隣接キーの磁気結合、レール電流と起動挙動、短期の温度ドリフト — D-011）。「測ってから凍結」を先に宣言する
- [ ] **感覚が絡む量の決定方法**：ピッチ等は「候補を全部作って実物で決める」と方法まで先に決める。コスト目標（100×100mm 等）は最適化目標であって製品形状への要求ではない、と格付けしておく（格付けを誤ると製品形状と喧嘩する — D-020）

### 3.2 インタフェース凍結

## 4. 電気設計の個別知見

- **引き出し混雑が本丸**：2層 0.20mm で残った16接続は全て MCU（U1）のパッドが端点。パッド間隔（0.40 ピッチ、隙間 0.20mm）には細線化しても新しい通路は開かない — 細線化の効果は引き出し後の余裕にしか出ない（#103 の検討）。
- **電源／GND は幅クラスを分ける**：全ネット一律 0.10mm だと幹線がなく、Wing の最遠センサは最悪条件で 4.5V を割った。信号 0.10mm／電源・GND 0.30mm のクラス分けで電圧降下は約1/3〜1/4 になり、全ケースで余裕が正になった（#141 → D-021 改定）。**配線の「完成」と電源インテグリティは別々に評価する。**
- **keepout の意味づけを明示する**：取付穴の keepout が「pads 禁止」を含んでいたため、穴自身が違反として残り続けた。禁止対象（tracks / vias / pads / pour）を設計定義で決め、生成側のデフォルトに任せない（#129 → #131）。
- **プレーン層の fill と予約領域**：取付穴の φ5 予約は GND プレーンにも効かせる（全層 keepout＋再充填）。後からの追い穴は、予約円が既存 fill に重なると成立しない（#153）。
- **局所修正の限界**：合格済み基板への局所退避は保持配線の被覆を壊して不合格になり、結局は除去範囲を固定した全体再配線1回で合格した（#155）。「壊してはいけない配線」の保持は、局所パッチより全体再実行の方が制御しやすい場面がある。逆に #167 再開時は局所修正が QSPI の保持配線を壊した（転送差分24）— 保持対象の差分検査なしに局所修正を許可しない。
- **センサ電源の感度**：Hall センサの推奨電圧域は離散的（DRV5055 は 3.0〜3.63V と 4.5〜5.5V）で、「3.3V 化で済ます」ような中間の緩和は構造的にできない。電圧を変える案は感度（出力スケール）への影響とセットで評価する（#165）。
- **給電デューティ化の罠**：枝スイッチを足す方式は、スイッチの直列損失で現行以下になった。省電力アイデアは「追加した素子の損失込み」で比較する（#165）。

## 5. 筐体・機構設計の個別知見

- **製品形態（ver.A の要件として記録済み）**：左右 Wing を逆ハの字に配置。基本形は角度固定の一体構成（基板固定機構のある底面部＋側面一体プレート、継ぎ目はほぼ底面のみ）。可変版は Main・左右 Wing が独立筐体＋回転接合。この2形態でも**基板の取付穴は共通の前提**になる — だから基板側の機構を先に確定させる順序が正しい。
- **評価用ハードに製品筐体は要らない**：M1 は評価が目的なので筐体なしと早期に切り分け、筐体検討の成果（寸法チェーン・インタフェース調査）だけを ver.A の入力に回した（#150 の扱い）。
- **コネクタ近傍の支持は筐体の要件**：基板の張り出し部にあるコネクタの抜去荷重は、基板のねじ固定だけに背負わせない（§3.3）。
- **一体パネルの分離**：左右一体基板は「製造上のパネル」であり、組立て前に自宅で分離する。分離接合は配線を傷めない形に設計する（§1.6）。
