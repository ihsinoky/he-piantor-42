# Issue #19 — native tscircuit Hall spike report

## Outcome and scope

This run stopped before Checkpoint A. The Codex Cloud environment could not
download the pinned stock `tscircuit` package, and it did not contain the pinned
Bun runtime. Consequently, no claim about native geometry, electrical design,
PCB generation, or manufacturing feasibility is made. This is **not** a GO or
NO-GO decision; that decision remains a Human Gate.

The run started at main commit
`44735c7538cb21230758ba9acd334621ba09ad55`. The existing KiCad designs,
firmware, Hall sensor selection, ADC/MUX architecture, and production layout
were not modified.

## Source-of-truth model

The intended experiment was native TypeScript/TSX as the candidate EDA
source-of-truth, with Circuit JSON and manufacturing outputs generated by stock
tscircuit. No KiCad importer, generated-file editing, schema fork, exporter
fork, or autorouter fork was used. Because dependency acquisition was blocked,
no TSX design or generated output was created.

## Tested versions and dependency reproducibility

The requested baseline was `tscircuit` **0.0.2646** and Bun **1.2.22**. Neither
version could be executed in this run:

- `npm view tscircuit@0.0.2646 version bin dependencies --json` returned
  `E403 Forbidden` for `https://registry.npmjs.org/tscircuit`.
- A direct `curl -I https://registry.npmjs.org/tscircuit` failed because the
  environment proxy rejected the CONNECT tunnel with HTTP 403.
- The installed Bun was 1.2.14, not the required 1.2.22.
- Node was v24.15.0 and npm was 11.4.2.

No alternative tscircuit version was selected. A lockfile could not be produced
without resolving the real stock dependency graph, so no fabricated or
hand-written lockfile was committed. `tsci --version`, `npm ci`, and the required
post-install lockfile-integrity check could not be run.

## Geometry provenance and Checkpoint A

The repository's existing
`hardware/lib/third_party/marbastlib-he.pretty/SW_MX_HE_0deg_1u.kicad_mod` was
read only as the permitted secondary reference. It identifies the Gateron
Magnetic Jade switch mechanical datasheet and contains the already verified
project geometry. It was not used as converter input and was not modified.

Checkpoint A was **not run**. In particular, the installed package types and
tests could not be inspected, so guessing the public API for `footprint`,
`smtpad`, `platedhole`, `hole`, or `keepout` would have violated the task.
There is therefore no native Hall component result and no machine-readable
geometry result.

### Native keepout result

Not evaluated. No keepout was authored, no `pcb_keepout` was generated, and no
copper-pour exclusion behavior was claimed. Advancing without the stock package
would require guessing API semantics or implementing a substitute, both of
which are expressly prohibited.

## Checkpoint B — electrical result

Not started because Checkpoint A did not pass. No Hall supply/output network,

## Checkpoint C — two-layer PCB result

Not started because Checkpoints A and B did not pass. No board, routing, or via
was generated.

## Available DRC/checks

Not evaluated. Without the exact stock installation, this run could not inspect
or execute the tool's actual design checks. Repository-owned assertions were
not substituted for unavailable stock design capability.

## Manufacturing results

Gerber, plated drill, NPTH drill, BOM, and pick-and-place results are all **not
generated**. No placeholders were added and no generated file was edited.
JLCPCB feasibility therefore remains unassessed; `FORMAT ADAPTER REQUIRED` is
not claimed because the underlying metadata was never generated.

## CI and evidence artifact

No Issue #19 workflow was added: a workflow using `npm ci` requires a committed,
genuine `package-lock.json`, which this environment could not create. Adding an
untested workflow or regenerating a lock in CI would violate the reproducibility
policy. There is no workflow run number or artifact ID. Existing
`engineering-ci` was not changed; no result for this branch was available in the
Codex Cloud task.

## Codex Cloud limitation

The environment forced npm and HTTPS traffic through `proxy:8080`; access to
the npm registry and GitHub raw content was rejected with HTTP 403. The required
Bun version was also absent. These are environment limitations rather than
evidence of a tscircuit product limitation. A fresh environment with registry
access and Bun 1.2.22 is required to resume the spike from Checkpoint A.

## Stock-only policy and custom repository code

Stock-only policy was maintained. There are zero lines of custom EDA,
validation, routing, exporter, or format-adapter code. The only repository
change is this evidence report. No hidden patch or workaround was introduced.

## Remaining unsupported or unverified features

All requested technical capabilities remain unverified: native Hall geometry,
native copper keepout semantics, structured electrical connectivity, exact
two-layer output, stock checks, Gerber and drill completeness, BOM identity,
pick-and-place fields, and JLCPCB feasibility.
