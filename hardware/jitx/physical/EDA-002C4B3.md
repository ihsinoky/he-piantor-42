## A. Thickness — cause and supported boundary

1. **Source thickness:** public `TestCase` and `visit(Stackup, Material)`
   independently measure mask/copper/core/copper/mask as
   0.015 / 0.035 / 1.10 / 0.035 / 0.015 mm: **1.20 mm including masks,
   1.17 mm excluding masks**. These are ordered material instances, each with
   its own public `thickness` in millimetres. This is not a standalone Board
   thickness field. See [independent measurements](c4b3-evidence/independent-source-measurements.json).

2. **Supported surfaces searched first:** official
   [Stackup/Material](https://docs.jitx.com/en/latest/api/jitx.stackup.html),
   [Board](https://docs.jitx.com/en/latest/api/jitx.board.html),
   [Substrate](https://docs.jitx.com/en/latest/api/jitx.substrate.html),
   [CLI](https://docs.jitx.com/en/latest/getting-started/cli/index.html),
   installed public APIs, CLI help and official JITX/substrate skills/examples.
   Board exposes shape/signal area; thickness belongs to materials.
   Installed `legacy-kicad --help` accepts only DESIGN, with no export setting.
   No supported overall-thickness override was found for these pinned versions.
   This is a bounded supported-surface finding, not a claim about future versions.
   [Research](c4b3-evidence/research.json), [API inspection](c4b3-evidence/supported-surfaces.json)
   and committed help outputs record the search.

3. **Root cause:** subsequent read-only inspection of the installed compiled
   runtime finds its KiCad PCB template contains a literal
   `(general (thickness 1.6))`, separately from `(setup {STACKUP} ...)`.
   The literal has no substitution placeholder. The installed Python legacy
   adapter delegates the design name and backend to this runtime.
   [Root-cause evidence](c4b3-evidence/thickness-root-cause.json) records the
   binary SHA-256, exact byte offset, template hash and short excerpt.
   The runtime does not ship the full exporter source, so no internal control
   flow or private setting is claimed. The literal template and repeated
   observed output establish fixed behavior in this export path. No public
   documentation of this limitation was found. Changing layer thicknesses
   cannot correct a separate literal; inventing `Board.thickness`, patching
   the template or calling private methods is not an accepted solution.

4. **Independent exported measurements:** both fresh runs preserve the five
   layer thicknesses and sum to 1.20 mm in `setup.stackup`; both declare
   `general.thickness = 1.6` and job `GeneralSpecs.BoardThickness = 1.6`.
   [Reconciliation](c4b3-evidence/reconciliation.json) records each measurement.
   This is an exporter inconsistency, not a mask-thickness convention:
   neither 1.20 nor 1.17 rounds to 1.6.

5. **Exactly affected outputs:** the generated `.kicad_pcb` overall thickness
   and the generated `*-job.gbrjob` overall BoardThickness are misleading.
   Within this demonstrated CAM inventory, the job is the only fabrication
   file affected by the overall-thickness value. The nine individual layer
   Gerbers, two PTH/NPTH Excellon files and 68-row positions describe planar
   features and do not specify overall finished board thickness. Their
   geometry, drill tools/coordinates and positions reconcile independently;
   the discrepancy does not move copper or change hole diameters. This is
   not a general qualification of STEP, impedance, all exporters or all DFM.
   The PCB must not be handed off as a trustworthy 1.2 mm CAD board.

6. **Supported limited handoff:** KiCad documents
   [Gerber job generation as optional](https://docs.kicad.org/9.0/en/pcbnew/pcbnew.html#fabrication-outputs-and-plotting).
   JLCPCB's current [KiCad 9 handoff requirements](https://jlcpcb.com/help/article/how-to-generate-gerber-and-drill-files-in-kicad-9)
   enumerate individual layers and Excellon, without requiring a job.
   JLCPCB provides [separate thickness selection](https://jlcpcb.com/blog/standard-pcb-thickness)
   and offers standard 1.2 mm FR-4. Thus selecting only unchanged Gerbers and
   drills for a fabrication ZIP, excluding the job and CAD files, is a normal
   handoff limitation; it does not repair exported metadata. The pinned CLI
   has no job-disable flag, so raw CAM retains the job and the handoff uses an
   explicit file whitelist. [Handoff evidence](c4b3-evidence/handoff.json)
   demonstrates nine Gerbers plus two drills with byte-for-byte archive checks.
   These ignored ZIPs are qualification-only and must not be uploaded/ordered.
   A future reviewed order specification must explicitly select 1.2 mm and
   reconcile finished-thickness convention/tolerance with the fabrication
   notes. This limitation must follow Rev.M1; it would merit
   PASS_WITH_LIMITATIONS for thickness alone, never automatic PASS.

## B. USB NPTH clearance — requirement and margin

The 0.25 mm value originates at
`QualificationFabRules.min_copper_hole_space` in the accepted C4B source.
Its docstring and C4B section 8 explicitly call the rules qualification
defaults. It is **not a cited manufacturer requirement or an existing product
policy**. The downstream project carries that value into DRC; C4B2 correctly
reported violations of the fixture rule. Historical conclusions remain valid.

The current [primary JLCPCB rigid-PCB capability table](https://jlcpcb.com/capabilities/pcb-capabilities),
accessed 2026-10-04, lists **NPTH to Track: 0.20 mm**. Its rigid FR-4 scope
includes this standard two-layer, nominal 1 oz process. This is not the flex,
HDI, blind-slot, inner-via or PTH clearance rule. The sealing-film explanation
supports treating the separation as NPTH-edge to adjacent copper; applying
it to these SMD lands is a conservative project interpretation. The published
hole-position tolerance is ±0.075 mm; the minimum is not a guarantee of a
finished gap. Do not add that tolerance mechanically to the design minimum
or claim the 0.25 mm target guarantees a worst-case manufactured gap.

Independent analytic measurements use the unchanged rectangular lands and
0.60 mm locator circles, with no circular display tessellation:

| USB port | Gap, mm | Margin above 0.20, mm | Disposition |
| --- | ---: | ---: | --- |
| A1_B12 | 0.2000999900 | 0.0000999900 | Marginal; release blocker |
| A12_B1 | 0.2000999900 | 0.0000999900 | Marginal; release blocker |
| A4_B9 | 0.2348831648 | 0.0348831648 | Nominal minimum met; below project target |
| A9_B4 | 0.2348831648 | 0.0348831648 | Nominal minimum met; below project target |

All four nominally meet 0.20 mm; none is declared numerically non-compliant
with that published minimum. The smaller pair has only **0.10 µm** headroom.
That is smaller than a 1 µm project numerical review guard, far below process
variation and the manufacturer's drawing precision. It is not comfortable
manufacturing margin. The source-to-export observer permits 0.001 mm shape
comparison error; this is an observer tolerance, not measurement uncertainty
or manufacturer tolerance. Analytic measurement resolves the nominal value,
but does not qualify production at that limit.

**Project-owned forward DFM policy for Rev.M1:** use 0.20 mm as the documented
capability floor and **0.25 mm as the recommended design target** for NPTH-edge
to copper. The extra 0.05 mm is a project margin choice, not a JLCPCB mandate.
Any fixed manufacturer landpattern below target requires a documented DFM
exception assessing actual geometry and process. A gap below **0.201 mm**
must not automatically pass release: the extra 0.001 mm is a project numerical
guard, not a vendor manufacturing allowance. Meeting the guard is necessary,
not sufficient, for an exception. The larger pair is eligible for margin
review; it has not been granted a production exception here. The near-limit
pair remains blocked without supported margin resolution or explicit process
qualification. No supplier contact, exception approval or yield evidence exists
in this increment. No footprint change, replacement or rule relaxation is used
to claim a pass. [DFM disposition](c4b3-evidence/dfm-disposition.json) separates
minimum, target, guard and the unchanged qualification rule.

## PMO answers and acceptance

1. **Cause:** fixed 1.6 mm literal in the pinned runtime's KiCad template,
   independent of the correctly serialized material stack.
2. **Supported preservation:** no correct overall CAD/job override found.
   Intended fabrication thickness can be specified independently with the
   normal job-free Gerber/drill handoff; carry this limitation into Rev.M1.
3. **Affected files:** `.kicad_pcb` general thickness and `.gbrjob` overall
   metadata; individual Gerber geometry, Excellon and positions are unaffected
   by this thickness discrepancy in the demonstrated workflow.
4. **0.25 origin:** conservative C4B qualification default.
5. **Current applicable requirement:** standard rigid FR-4 NPTH-to-track
   capability floor 0.20 mm, conservatively applied to adjacent pad copper.
6. **Four gaps:** smaller pair marginal/blocking; larger pair nominally
   acceptable against minimum but requires project target exception review.
7. **Forward project rule:** 0.20 floor / 0.25 target / 0.001 numerical guard;
   documented exceptions required, no blanket manufacturer-footprint waiver.
8. **Only routing remains? No.** USB manufacturing margin remains unresolved.
   Thickness is a documented supported handoff limitation; library registration,
   supplier rotation and BOM sourcing remain separate known limitations.

Task acceptance: investigation and reproducible evidence complete;
manufacturing release **BLOCKED**. No Main/Wing or G0B work, topology changes,
autorouter, full routing, order, D-016 or adoption decision. PMO reviews this
disposition; PO decides MERGE/HOLD. C4C/G0A remains a later Human Gate.
