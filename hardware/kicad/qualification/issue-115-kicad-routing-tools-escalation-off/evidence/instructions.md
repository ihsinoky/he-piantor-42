## 目的

#113 で KRT は Main 未配線5件（全候補中最良の接続性）を記録したが、公式デフォルトの fab escalation が 0.127mm トラック271本と出力プロジェクトの下限書き戻し（0.20→0.127mm 等）を行い、固定条件では不合格だった。本 Issue は変更を escalation の無効化だけに限定し、KRT の実条件での判定を行う。fastroute #99 と同じ論法（文書化された下限違反の仕組みを切り、下限を実条件に固定する）である。

- 入力基板は #113 で固定・保存したものを再利用し、実行前に SHA256 を照合する

- 経路例外（KiCad ネイティブ直接編集）は本候補限りで継続する

## 等価性ゲートの完遂（#113 の手順不足の解消）

#113 では、フットプリントの表裏と未使用ネットを含む全ネット定義の明示照合が Main 起動後の補足となり、「厳密な事前ゲート適合は未認定」となった。今回は次を **配線実行の前に** すべて明示検査し終え、ゲート通過の記録（時刻付き）を残すこと。

1. #113 の事前検査項目（配置、各パッドのネット/形状/層、ルール、既存配線）
2. フットプリント自体の表裏（native footprint layer と DSN front/back の対応）
3. 未使用ネットを含む全ネット定義（native net 定義と DSN network の対応）

入力が #113 の固定コピーと同一（hash 一致）であることが前提であり、基板の修正は禁止。

## 単一条件の特定（Main 実行前に確定）

1. escalation を無効化する正確な方法を、公式 README・`--help`・ソース（`routing_defaults.py`、`fab_tiers.py`）の一次資料で特定する。#113 報告書には `--escalation off` という切替の存在が記されているが、正確な引数形・効き方は自ら裏付けること
2. Main 実行の前に、実効設定の読み戻し（ルーターが解決した全パラメータ）を取得し、#113 のデフォルト実行時と比較する。**差分が escalation 無効化のみ** であることを文書で示す。他の設定が連動して変わる場合は、その事実を記録したうえで、それ以上は寄せない（連動を打ち消す追加指定は設定探索に当たるため行わない）
3. スモークも同じ条件で実行する（条件は Stage 0 から同一）

## 固定条件

- 配置固定、配線幅・クリアランス 0.20mm、2層。その他の条件変更・設定探索は禁止

## 実行手順（二段構え）

### Stage 0（スモーク）
- escalation 無効の条件で1回実行し、出力基板への独立検査（#113 と同一手法）で4指標すべて0を確認する。失敗したら Main に進まない

### Stage 1（Main）
- 同一条件で1回だけ実行する

## 判定（#113 と同一基準＋1項目）

成功条件（すべて）：
- 未配線 0
- 出力基板の全トラックが 0.20mm 以上（静的実測）
- 独立検査で4指標（required unconnected / wrong-net contacts / material violations / unexplained transfer changes）すべて 0
- **出力プロジェクトの下限（min_track_width／min_clearance／min_via_diameter 等）が元の値のまま書き戻されていないこと**（KRT が .kicad_pro を書き換える場合、その内容を全件列挙する。書き戻しがあれば、それ自体を失敗条件とする）

失敗条件（いずれか1つ）：
- 未配線が残る／0.20mm 未満のトラックがある／配線追加以外の説明のない差分がある／下限の書き戻しがある／headless 実行不可／2時間内に結論が出ない

4指標の扱い：未配線が残る場合は **null** とし、未配線件数を実測報告する
